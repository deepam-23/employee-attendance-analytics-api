# Starter code review

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Replacing the punch-in's hour with the shift hour ignores IST conversion and overnight shift dates; it can produce a negative or incorrect elapsed time. | Test a UTC instant near midnight for a 22:00-06:00 shift, or a punch-in just after the 10-minute grace period. | Convert to IST, anchor the shift to the attendance day, and apply the strict 10-minute rule using whole seconds. |
| 2 | `compute_work_hours` | Built-in `round` uses ties-to-even, not the required decimal half-up rounding; negative or overlong intervals are not rejected here. | Use a duration exactly halfway between hundredths, or try punch-out before punch-in. | Calculate from validated instants and round with `Decimal`/`ROUND_HALF_UP`; validate punch-out business rules at the endpoint. |
| 3 | `compute_overtime` | The shift end is always placed on the attendance date, even for overnight shifts, and any positive overtime is counted rather than requiring at least 30 minutes. `replace(tzinfo=...)` also misinterprets already-aware instants. | Test a 22:00-06:00 shift or a punch-out 29 minutes after shift end. | Build the correct IST shift-end instant on the following day for overnight shifts; count only whole minutes at or above 30. |
| 4 | `health` | Always reports ready without checking whether MongoDB can answer requests. | Stop MongoDB and call `/health`; the starter still returns 200. | Ping MongoDB and return 503 when it is unavailable. |
| 5 | `create_employee` / `EmployeeIn` | The pre-insert duplicate check races under concurrent requests without a unique database constraint. The created timestamp is naive and returned as an ISO string instead of epoch milliseconds; required format and shift-time rules are not validated. | Send concurrent creates with the same code, malformed fields, or inspect `created_at`. | Add an idempotent unique index, translate duplicate-key errors to 409, validate inputs, and store/return a UTC instant in milliseconds. |
| 6 | `list_employees` | The skip is `page * page_size`, so page 1 skips the first page. `total` ignores the department filter, and results are unsorted with no page bounds. | Request page 1 and page 2; compare totals with a department filter. | Use `(page - 1) * page_size`, count the filtered query, sort by `emp_code`, and enforce pagination limits. |
| 7 | `punch_in` | A missing employee is dereferenced; timestamps use the host's local timezone, are not truncated or range-checked, and `0` is mistaken for omission. Status is unrestricted. The check-then-insert duplicate logic is not concurrency-safe. | Try an unknown code, an invalid timestamp/status, or parallel same-day punches. | Validate epoch milliseconds/status, derive the IST attendance day (including overnight shifts), return 404 for unknown employees, and rely on the unique natural-key index for race-safe 409 responses. |
| 8 | `list_attendance` | It reads and sorts the entire collection in Python, which does not scale; dates are not validated as an ordered range and MongoDB `_id` is exposed as an `id`. | Seed many records, request a page, or send `date_from > date_to`; inspect response fields. | Count and page in MongoDB with deterministic sorting, validate the range, and serialize only contract fields with epoch-millisecond instants. |
| 9 | Endpoint coverage | Punch-out, regularization/audit history, all four analytics endpoints, and the explain endpoint are missing. | Call each contract path; each returns 404. | Implement each path, including atomic punch-out/regularization updates and the required MongoDB aggregation pipelines. |

**Reviewed but not a defect:** `compute_work_hours` correctly expresses elapsed duration in hours; its defect is its rounding policy and lack of endpoint validation, not the basic duration formula. Using `emp_code` rather than MongoDB `_id` as the employee key is also correct and is preserved.
